## Architecture (brief)

**Context:** Gameplay is feature-complete. Portfolio needs evidence of measurement, not folklore. Plan forbids a GPU/console rabbit hole.

**Shape:** Fixed scenario: 4 players + bot, ~2 min, same map, same actions. **Before:** `-trace=default,net -NetTrace=1` (or `cpu,gpu,frame,net`), screenshots in `docs/perf/before/`. Then pick **3–4** items from the plan list (disable unused Tick, `NetUpdateFrequency`, cull distance, projectile/Niagara lifetime, BT/perception frequency). **After:** same scenario, `docs/perf/after/` + table in `docs/perf/README.md` (Game thread ms, KB/s per client, or bits/actor). Feel polish last: shake, SFX, light hit-stop, arena lighting — no new systems.

**Alternatives:**  
A) **(Recommended)** Measure → change 3–4 knobs → measure (plan).  
B) Rewrite replication to push model — high risk, not needed.  
C) Polish VFX for days before capturing “before” — loses the Insights story.

**Consequences:** + README/video have a real table. − Scenario must be repeatable or the table is dishonest. Rigid: do not add features in this milestone.

**Contracts:** Capture command line documented. Table columns: metric, before, after, what changed. At least **2** metrics move.

**NFRs:** `stat unit`, `stat game`, `stat net` during captures. No new Tick-heavy debug.

**Implementation order:** freeze content → before capture → optimizations → after capture → table → feel/README v1 draft.
