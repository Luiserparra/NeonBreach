## Architecture (brief)

**Context:** M2 health is a raw replicated float. Portfolio needs GAS: ASC, AttributeSet, Gameplay Effects, tags. Fire must stay predicted (cosmetic + cost/cooldown pattern for later abilities).

**Shape:** `UAbilitySystemComponent` on **PlayerState**, `ReplicationMode = Mixed`. `ANBCharacter` implements `IAbilitySystemInterface` and returns the PlayerState ASC. Init: `PossessedBy` (server) and `OnRep_PlayerState` (client). `UNBAttributeSet`: Health, MaxHealth, Energy, MaxEnergy, EnergyRegen, IncomingDamage (meta, not replicated). `UNBGA_Fire` LocalPredicted: client FX; server trace + `GE_Damage`. Remove M2’s direct Health subtract.

**Alternatives:**  
A) **(Recommended)** ASC on PlayerState — health survives pawn respawn; GAS community default for player-controlled characters.  
B) ASC on Character — simpler init, state lost on respawn unless copied.  
C) Keep M2 fire RPC forever — no GAS in the portfolio.

**Consequences:** + Respawn does not re-grant a blank ASC. − Init timing (`OnRep_PlayerState`) is the usual bug farm. Bot (M8) will use ASC **on the Character** (`Minimal` replication) because it has no PlayerState ASC owner in the same way — document that split.

**Contracts:** Tags `Ability.Fire`, `Data.Damage`, `Event.Hit`, `State.Dead`. `GE_InitStats`, `GE_Damage` (Instant, SetByCaller `Data.Damage` → IncomingDamage). `GE_EnergyRegen` Infinite periodic (energy not spent by fire yet).

**NFRs:** Same 3-client PIE test as M2; fire still instant locally. No new abilities this milestone.

**Implementation order:** AttributeSet + replication → ASC init → grant `GA_Fire` / `GE_InitStats` → migrate trace into ability → delete M2 health subtract.

## Networking notes

- **Mixed** ASC: owner gets full GE/tag replication; others get minimal (enough for death/health bars later).
- `GA_Fire` LocalPredicted: client runs the ability immediately (FX). Server runs it independently and applies `GE_Damage`. Prediction mismatch = ghost tracer, not HP desync (HP is server).
- Never apply `GE_Damage` from a client-only path. `HasAuthority()` or `GetOwningActor()->HasAuthority()` inside the ability before SetByCaller.
- Attribute replication is GAS’s job; do not also replicate M2’s old Health float — remove it to avoid two truths.

Init pitfalls (teach in the lesson later): granting abilities twice (possess + OnRep), ASC null on first client frame, PlayerState not ready.
