# M8 — Behavior Tree bot + full loop in a Windows build

**Goal:** One server-only bot (patrol / investigate / combat via GAS) appears on the scoreboard, and 2 humans + 1 bot complete lobby → match → victory in a packaged Windows build.

**Status:** Not started  
**Plan:** Week 4, days 3–5 · **Tag:** `v0.4`  
**Depends on:** M7 (`v0.3.1`)

---

## Architecture (brief)

**Context:** Humans play the loop. MVP needs one bot recruiters can debug (`'` Gameplay Debugger). Plan chose Behavior Tree over StateTree (interview familiarity + live tree view).

**Shape:** `ANBBotCharacter` (or `ANBCharacter` with bot flag) spawned by GameMode. **ASC on the Character**, `ReplicationMode = Minimal` (no PlayerState ASC). `ANBAIController` + AIPerception (Sight). Blackboard: `TargetActor`, `LastKnownLocation`, `PatrolLocation`, `HasLineOfSight`. C++: `UBTService_UpdateTarget`, `UBTTask_FireAtTarget` (activate `GA_Fire` by tag), `UBTTask_UseAbility` (Dash if Health < 40). Tree: Combat / Investigate / Patrol as in plan §8. Aim spread ±3°. Bot has `ANBPlayerState` (or equivalent) so K/D shows on the scoreboard — GameMode gives the bot a PlayerState.

**Alternatives:**  
A) **(Recommended)** Behavior Tree + Blackboard + C++ tasks (plan).  
B) StateTree — evaluated alternative, README later, not MVP.  
C) Hard-coded Tick ChasePlayer — not portfolio-grade.

**Consequences:** + Same GAS pipeline as players (Fire/Dash). − NavMesh required on `L_Arena`. EQS strafe is optional (cut order #3). Rigid: AIController exists **only on the server**; character still replicates.

**Contracts:** Bot uses `Ability.Fire` / `Ability.Dash` tags, not a parallel damage cheat. Perception config in BP. NavMesh bounds on arena.

**NFRs:** Full loop in **packaged** build: lobby → match → victory → lobby/rematch. Gameplay Debugger clip is for the video (M10) but should work now.

**Implementation order:** NavMesh + bot pawn → AIController + perception → Patrol BT → Investigate → FireAtTarget → Dash decorator → scoreboard → packaged loop.

## Networking notes

AIController and BT run **server-only**. The bot pawn replicates like a player (location, ASC Minimal, cues). Clients must not spawn their own bot. Shots still go through `GA_Fire` (server trace + GE_Damage). If the bot needs a PlayerState for the scoreboard, create it on the server only.

Perception and FireAtTarget must not run on SimulatedProxy.
