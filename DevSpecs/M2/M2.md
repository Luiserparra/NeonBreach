# M2 — Networked hitscan, health, death, respawn

**Goal:** Three PIE clients shoot each other with a server-authoritative line trace, die, and respawn; the listen-server host has no gameplay-logic advantage.

**Status:** Not started  
**Plan:** Week 1, days 3–5 · **Tag:** `v0.1`  
**Depends on:** M1 (`v0.0`)

---

## Architecture (brief)

**Context:** No GAS yet. Need a recruiter-visible pattern: client predicts cosmetics, server validates the shot and applies damage.

**Shape:** Fire input → local muzzle/tracer immediately → `ServerFire(Origin, Direction)` RPC. Server re-traces from its weapon socket, rejects absurd range/angle, applies damage to a **replicated Health** on `ANBPlayerState`. Death sets a flag; `ANBGameMode` respawns at a PlayerStart. Other clients see shot FX via **NetMulticast Unreliable**.

**Alternatives:**  
A) **(Recommended)** Temporary `float Health` + `OnRep` on `ANBPlayerState` (same actor that will own the ASC in M3).  
B) Health on `ANBCharacter` — dies on respawn possession churn.  
C) Skip multicast and use only local FX — other players see no shots.

**Consequences:** + Clear RPC lesson; M3 migrates damage to `GE_Damage` without moving state off PlayerState. − Week-1 health is throwaway once AttributeSet lands. No lag compensation / rewind (documented later as a next step).

**Contracts:** `ServerFire` Server RPC (reliable); `MulticastShotFX` NetMulticast unreliable. Health + bDead replicated. Damage numbers in a Data Asset or `UPROPERTY` on the weapon component (12 dmg, 8 shots/s) — not magic numbers in the RPC.

**NFRs:** 3 PIE clients + Network Emulation **Average**. Host and clients use the same fire path (`HasAuthority()` only for apply-damage / trace authority).

**Implementation order:** fire rate + local FX → Server RPC + trace → health/death → GameMode respawn → arena blockout → 3-client lag test.

## Networking notes

| Action | Client | Server |
|---|---|---|
| Input Fire | Predicts FX | — |
| Trace + damage | Never applies | Re-trace, `ApplyDamage` / subtract Health |
| Death / respawn | Displays OnRep | GameMode only |
| Shot FX for others | — | Multicast Unreliable |

Prediction is **cosmetic only**. If the server rejects the shot, the shooter may see a ghost tracer — acceptable for M2. Test **Play As Client** so the “host window” is not a listen-server pawn with a different code path. Listen server is still the itch.io target; PIE dedicated client proves authority.

Validation: reject traces whose origin is far from the pawn’s muzzle, or direction wildly off aim, or range beyond weapon max.
