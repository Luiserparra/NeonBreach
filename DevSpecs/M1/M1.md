# M1 — Project foundation, NB classes, Enhanced Input

**Goal:** Lock UE 5.8, own NB-prefixed gameplay classes, and move two PIE clients with Enhanced Input bound in C++.

**Status:** Not started  
**Plan:** Week 1, days 1–2 · **Tag:** `v0.0`  
**Depends on:** nothing (first milestone)

---

## Architecture (brief)

**Context:** Existing Third Person C++ project (UE 5.8) still uses template `ANeonBreachCharacter` / `ANeonBreachGameMode` plus unused `Variant_*` samples. NeonBreach must be a listen-server arena with C++ logic and Blueprint content — not Lyra, not the combat variant.

**Shape:** New `ANB*` / `UNB*` stubs under `Source/NeonBreach/`. `ANBCharacter` owns camera boom + follow camera (copy the template pattern). Input is Enhanced Input: Mapping Context applied in C++, actions are data assets. Default GameMode / maps point at NB assets.

**Alternatives:**  
A) Rename template classes in place — faster, NB prefix and folder layout stay messy.  
B) **(Recommended)** New NB classes; leave template + `Variant_*` in the repo unused (do not delete in M1).  
C) Strip variants now — compile risk and no gameplay value this week.

**Consequences:** + Clean prefix and GAS/net hooks later. − Two character classes exist until variants are ignored. Rigid: engine version stays **5.8** for the whole project.

**Contracts:** `IMC_Default` + `IA_Move`, `IA_Look`, `IA_Jump`, `IA_Fire`, `IA_Ability1–3`, `IA_Scoreboard`. Startup map still the Third Person level (arena map is M2). GameMode default = `BP_NBGameMode`.

**NFRs:** Compiles with no project-code errors. PIE 2 clients, **Play As Client** (internal dedicated server) so movement is not host-only.

**Implementation order:** plugins + `Build.cs` → empty C++ classes → Input assets → `BP_` children → Project Settings → PIE.
