# M5 — HUD: vitals, cooldowns, crosshair, hit marker

**Goal:** A C++ `UNBHUDWidget` (BindWidget) shows replicated Health/Energy, three ability cooldowns, a crosshair, and a hit marker — presentation only, no gameplay truth.

**Status:** Not started  
**Plan:** Week 3, days 1–2 · **Tag:** `v0.2.1`  
**Depends on:** M4 (`v0.2`)

---

## Architecture (brief)

**Context:** Attributes and cooldown tags already replicate. Players still read logs. HUD must react, never decide damage/score.

**Shape:** `UNBHUDWidget : UUserWidget` with `meta=(BindWidget)` for bars/text/images. `ANBPlayerController` creates the widget on possess (local player only). Widget **listens**: AttributeSet delegates / ASC tag events (`Cooldown.Ability.*`, `State.Barrier`). Hit marker: local event when owner’s `GA_Fire` server confirms a hit (`Event.Hit` or a client RPC/callback from the ability) — not a second damage system.

**Alternatives:**  
A) **(Recommended)** C++ widget base + BP layout (plan §4.3).  
B) Pure UMG Blueprint graphs reading the pawn — logic leaks into BP.  
C) UMG in GameMode — wrong ownership; HUD is a local PlayerController concern.

**Consequences:** + Layout iterable in Designer without touching C++. − BindWidget names must match BP. Rigid: widget never calls `ApplyGameplayEffect`.

**Contracts:** BindWidget names documented in the header (`HealthBar`, `EnergyBar`, `DashCooldown`, `OrbCooldown`, `BarrierCooldown`, `Crosshair`, `HitMarker`). Cooldown UI starts immediately because GAS predicts cost/CD GEs (plan §5.3).

**NFRs:** Local-only widget (no replication of UMG). Works for listen-server host and PIE clients.

**Implementation order:** widget C++ + empty BP → bind health/energy → cooldown tags → crosshair → hit marker.

## Networking notes

UI is **client presentation**. It reads replicated attributes/tags. If a cooldown icon ticks before the server ACK, that is predicted GAS — correct. Hit marker must not fire on a predicted trace that the server rejected (wait for `Event.Hit` / GE applied to a target, or an owner-only client RPC from the server ability). Never run damage math in the widget.
