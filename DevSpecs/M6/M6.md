## Architecture (brief)

**Context:** Combat works; there is no match. Truth for score/phase/time must live on the server (`ANBGameMode` mutates, `ANBGameState` replicates, HUD reacts).

**Shape:** `enum class ENBMatchPhase : uint8 { WaitingToStart, Warmup, InProgress, PostMatch }`. Replicated on `ANBGameState` with `OnRep_MatchPhase`. GameMode: 5 s warmup (no damage), then FFA until **10 kills** or **5:00**; PostMatch 10 s (input locked, winner camera if cheap); Host Rematch = `RestartGame` / travel same map. Score: +1 kill, bot later counts, suicide/fall −1. Kill feed: GameState `NetMulticast Reliable` (Killer, Victim). Scoreboard: Tab (`IA_Scoreboard`) reads PlayerState Kills/Deaths.

**Alternatives:**  
A) **(Recommended)** Custom phase enum on GameState (plan §6) — explicit, HUD-friendly, works with GameModeBase.  
B) Engine `AGameMode` match states — less control over Warmup/PostMatch lengths.  
C) Phase only on GameMode — clients cannot display timer without extra RPCs.

**Consequences:** + One OnRep drives countdown, damage gate, victory widget. − PIE seamless travel is deferred (M7); Rematch can `RestartGame` on the same map. Rigid: victory and score only on server.

**Contracts:** `ANBPlayerState` replicated Kills/Deaths (`OnRep_Score`). `ANBGameState`: Phase, TimeRemaining, WinnerPS. Damage gate: GameMode or a world tag `State.Warmup` — **server rejects damage** when not `InProgress`.

**NFRs:** Packaged Windows build tested with 2 instances (or 2 PCs) if possible; otherwise 3-client PIE + one Standalone. Plan note: seamless travel is weak in PIE — do not block M6 on it.

**Implementation order:** PlayerState score → GameState phase/timer → damage gate + warmup → kill feed + scoreboard → PostMatch + Rematch → package.

## Networking notes

Phase, time, winner, Kills/Deaths are **replicated state**. Kill feed is **Reliable multicast** (rare events). Clients never increment score. Warmup: even if a client predicts fire FX, server must not apply `GE_Damage`. Test Play As Client so the dedicated PIE server runs GameMode (not the human host window). Listen-server Host is the real product; GameMode still `HasAuthority()`-only.
